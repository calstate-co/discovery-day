# Stage 2 - Implement

## Purpose and milestone

Purpose: turn the approved Site Brief into a working one-page website and, with permission, a private Sites preview the attendee can see and use.

Milestone: the attendee has explicitly authorized a workspace-private preview, and that rendered preview is visibly open in the built-in browser side panel.

## Confirm implementation details

Before building, ask a small set of focused questions when the Site Brief does not already answer them:

1. Which content, images, or links should be included in this first version?
2. Which items should remain clearly labeled placeholders for now?
3. Which interactions or buttons need to work in this first version?

Use the answers to keep the first build aligned with the attendee's goals and to avoid implying that unfinished content or behavior is complete.

## Build the first version

Use the stage label **Adventure A - Stage 2 of 4: Implement**. Briefly recap the approved Site Brief and name any unresolved assumptions before building.

Build only the agreed first version. Use real attendee-provided material when available; otherwise use clearly generic placeholder content that can be replaced. Keep the page responsive, readable, and keyboard-friendly. Do not add features merely because they are technically possible.

Recommend creating a private Sites preview before publication. Explain that the rendered preview lets the attendee see and use the actual site, mark specific changes with browser annotations, and work through refinements before the site is published more broadly.

Then ask a direct question such as:

> Shall I create a private Sites preview for you to review? It will be available only within this workspace and will not be public.

Wait for a clear yes. Then use Sites to create the attendee's own private preview and open its URL visibly in the built-in browser side panel. Tell the attendee that this preview will be the review surface for the Refine stage. Each attendee receives a site-specific preview URL; do not reuse or describe another attendee's URL as a general link. When giving the URL to the attendee, label it **Open in the ChatGPT side panel** and provide it as copyable text. Explain that a normal chat link may open a separate browser, so they should open the ChatGPT app's side panel and paste the URL there.

Before moving to Refine, explain what annotations are: comments attached to a specific part of the rendered page. Give beginner-friendly instructions to turn on annotation mode, select or mark the page area, describe the requested change, save the comment, and return to chat. State clearly that, for this workflow, annotation controls are available only through the ChatGPT app's side panel and not in a regular web browser. If annotation mode is unavailable, offer chat-based feedback using the section name and desired change instead.

Inspect the rendered private page, not only the source code or a successful build command. Do not require the attendee to run a local web server, use a port, or install development software.

If the private preview cannot be created or opened in the built-in browser, explain the blocker and keep the site unpublished. Do not say it is ready for annotation or refinement until the attendee can see the rendered private page.

## Stage close

Summarize what was built, what uses placeholder content, and where the private preview is open. State whether the preview milestone is complete, and ask whether the attendee wants to continue unless they have already clearly asked to proceed. When complete, announce Stage 2 complete and direct the attendee to the **2 Implement booth** to collect the Implement stamp. Explain that the four core stamps qualify them for the raffle. For access or troubleshooting, direct them to the **IT Support booth in Anacapa**.
