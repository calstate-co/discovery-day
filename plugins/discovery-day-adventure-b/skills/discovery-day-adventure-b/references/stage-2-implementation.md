# Stage 2 - Implement

## Purpose and milestone

Purpose: convert the confirmed Preparation Brief into a working one-off planner.

Milestone: every selected source is either verified or clearly excluded for the preview, and the attendee can inspect the first generated result.

## Reconfirm the build target

Start with the stage label **Adventure B - Stage 2 of 4: Implement** and a short recap of the confirmed Preparation Brief. Call out unresolved assumptions before acting.

## Connect and verify apps

For each selected app:

1. use a harmless read-only profile, list, or search action when available;
2. if connection is required, explain exactly what the attendee needs to click or approve in ChatGPT;
3. pause work on that source while sign-in or approval is pending;
4. continue with connected sources if the attendee wants; and
5. record unavailable or intentionally omitted sources in the preview.

Never accept credentials in chat. Never claim a source was reviewed merely because its app appears in the source list.

## Draft the task specification

Translate the brief into a clear imperative that tells the task:

- which week to analyze;
- which sources and scopes to review;
- how to apply the vacation or out-of-office skip rule;
- what evidence to extract;
- what must not be modified;
- what the Weekly Preparation Planner must contain; and
- how to handle missing source material without fabrication.

Use the weekly planner blueprint for useful defaults, but preserve the attendee's choices.

## Build a one-off preview first

Generate a one-off planner using the same logic intended for the recurring task. This preview is the implementation proof. Do not activate recurrence during this stage.

When source access is incomplete, label the preview as partial and list the omitted sources. Do not fill gaps with plausible-looking content.

If the attendee's absence rule triggers during the preview, state clearly that only the normal planner output is being skipped; the Implement stage itself continues. Show the skip result as one test outcome, then offer to build a full preview for the next non-vacation workweek so the attendee can still evaluate the planner. Do not silently change the approved absence rule.

For HTML output, prefer a self-contained Weekly Preparation Planner with clear headings, a readable timeline, working links where available, and accessible controls. Do not depend on remote scripts or styles unless the environment explicitly supports them.

## Review the implementation result

Explain what was actually reviewed, what was unavailable, and what the preview produced. Point the attendee to the Weekly Preparation Planner and ask them to inspect it.

When the result is usable enough to test, confirm that no recurring task was created or activated. If the Scheduled view is available, tell the attendee how to use it to verify that there is no new task yet. Announce that Stage 2 is complete and direct them to the **2 Implement booth** to collect the Implement stamp on their Discovery Day stamp card. Remind them that the four core stamps qualify them for the raffle.
